# Pilot test #143

สถานะ: **เตรียมพร้อมทดลอง — ยังไม่รันกับผู้เข้าร่วม** ไม่มีการนำ automated E2E หรือการทดสอบ iOS เดิมมานับเป็น pilot รอบนี้

จุดประสงค์คือดูว่าคนที่ไม่คุ้นกับระบบค้นหา TOR เข้าใจผลและทำงานหลักได้เองหรือไม่ สำหรับงานส่งอาจารย์เริ่มจากผู้เข้าร่วม 3–5 คนได้ ไม่ใช่จำนวนที่ SRS บังคับ ใช้เวลาประมาณ 15–20 นาทีต่อคนและระบบ/ฐานข้อมูลทดสอบเท่านั้น

## เตรียมก่อนเริ่ม

- ใช้ build/commit เดียวกันตลอดรอบ และบันทึก OS/device/browser version
- เตรียม TOR จำลองที่สกัดแล้วอย่างน้อย 3 รายการ ราคา 500,000 / 1,000,000 / 2,000,000 บาท มี scope/qualifications/confidence ให้ตรวจได้
- ใช้บัญชีทดสอบที่อนุญาตใน Google OAuth และ profile บริษัทสมมติ ห้ามใช้บัญชีที่เก็บข้อมูลสำคัญ โดยเฉพาะ task ลบบัญชี
- ไม่ต้องเปิด live scraper หรือส่งเอกสารไป AI เพื่อทำ pilot ของหน้าค้นหา ใช้ผลสกัดที่เก็บไว้แล้ว ถ้าจะทดสอบ ingestion/extraction ด้วยต้องผ่าน source policy และ payload review ตาม README QA
- อธิบายว่าจะเก็บเฉพาะรหัส P01/P02/… เวลาทำงาน ผลสำเร็จ และ feedback ไม่บันทึกอีเมล ชื่อ รหัสผ่าน JWT หรือ Google consent screen หากจะอัดหน้าจอต้องขออนุญาตก่อน
- ให้ผู้ทดสอบบอกสิ่งที่กำลังคิด ผู้สังเกตไม่สอนวิธีทำ เว้นแต่ติดจนทำต่อไม่ได้ แล้วลงว่า needed_help

## สถานการณ์ทดลอง

| ID | บอกผู้เข้าร่วม | ผลที่คาดหวัง | สิ่งที่จด |
|---|---|---|---|
| P-01 | เข้าสู่ระบบและหาหน้าโปรไฟล์ แล้วอ่านการใช้ข้อมูล | Login สำเร็จ พบ notice/consent; ยังไม่ติ๊กยินยอมให้อัตโนมัติ | เวลา ความเข้าใจ จุดที่หลง |
| P-02 | ใช้คำว่า “เว็บไซต์” หาโครงการ แล้วลองคำที่ไม่มีผลและกลับรายการเดิม | พบโครงการ website และกลับจาก no-results ได้ | จำนวนครั้งที่ลอง / ต้องช่วยหรือไม่ |
| P-03 | หาโครงการราคาตั้งแต่ 500,000 ถึง 1,000,000 บาท แล้วเรียงตามราคา | ได้สองรายการที่ขอบทั้งสองค่า และอ่านลำดับได้ | เข้าใจว่าตัวกรองเป็นทางเลือกหรือคิดว่าต้องทำทุก step |
| P-04 | เปิดโครงการแล้วอธิบาย scope/คุณสมบัติ/ราคา และคะแนนความเชื่อมั่น | อ่านรายละเอียดได้ แยก confidence จาก matching score และรู้ว่าค่าต่ำควรตรวจต้นฉบับ | คำอธิบายสั้น ๆ / ความเข้าใจผิด |
| P-05 | บันทึกโครงการและกลับไปหาในรายการที่บันทึก | เปิดโครงการเดิมจาก bookmarks ได้ | สำเร็จ/ไม่สำเร็จและเวลา |
| P-06 | ยินยอมใช้โปรไฟล์แล้วกรอกบริษัทสมมติ บันทึก จากนั้นถอนความยินยอม | ข้อมูลคงอยู่เมื่อ reload; ถอนแล้ว matching/save ที่ต้องอาศัย consent ถูกจำกัด | ความชัดเจนของข้อความ/ปุ่ม |
| P-07 | ส่งออกข้อมูลของบัญชีทดสอบ และลบบัญชีทดสอบหลังจบ | ได้ JSON ของบัญชีตนเอง ยืนยันลบชัดเจน และ session เดิมใช้ไม่ได้ | ความมั่นใจ/ความกังวล; ห้ามลบบัญชีจริง |

หาก runtime ไม่ได้ตั้ง Google OAuth ให้ลง P-01 blocked และใช้ session ทดสอบที่เตรียมโดยผู้ดูแลสำหรับงานอื่น ระบุในผลว่าไม่ได้ทดสอบ provider จริง ห้ามให้ผู้เข้าร่วมใส่ token ผ่าน console เอง

## แบบบันทึก

คัดลอก `pilot-results-template.csv` เป็นไฟล์ผลรอบจริง เก็บรหัสผู้เข้าร่วมเท่านั้น ผลต่อ task ใช้ `completed`, `needed_help`, `failed`, `blocked`, `not_run` ลงเวลาจริงและอาการที่พบ ไม่เติม PASS จากการคาดเดา

หลังจบถามคะแนน 1–5: ค้นหาได้ง่ายแค่ไหน / เข้าใจราคาและ confidence แค่ไหน / มั่นใจเรื่อง profile-consent แค่ไหน และถามคำถามปลายเปิด “ส่วนไหนสับสนที่สุด” กับ “อยากแก้อะไรก่อน” ไม่ใช้คำถามชี้นำว่าระบบดีหรือไม่

เกณฑ์เสนอสำหรับ demo (ให้ตกลงก่อนเริ่ม): งานค้นหา/ราคา/รายละเอียด/บันทึกอย่างน้อย 80% ของโอกาสทำ task สำเร็จโดยไม่ช่วย และไม่มีปัญหารุนแรงเรื่องข้อมูลคนอื่นหรือการลบข้อมูลผิดบัญชี รายงานจำนวนผู้เข้าร่วม ตัวหาร task ที่ทำจริง และ blocked แยกต่างหาก ขนาดตัวอย่างเล็กไม่แทน usability ของประชากรทั้งหมด

## สรุปและตรวจซ้ำ

รวม completion rate/เวลามัธยฐานของแต่ละ task, help count, คะแนน/ข้อเสนอแนะ และปัญหาตามความรุนแรง เชื่อม defect กับ issue และตรวจซ้ำหลังแก้พร้อม commit ที่ใช้ ท้ายรายงานระบุข้อจำกัดของกลุ่มผู้ทดลองและอุปกรณ์ เมื่อมีผู้เข้าร่วมและผลจริงจึงเปลี่ยน #143 เป็นผ่านหรือไม่ผ่าน ยังไม่ปิด issue จากเอกสารเตรียมทดลองนี้
