## User data restriction — always applies

Real application databases and records may be read and copied only. This applies
to production, shared databases and persistent local development databases
(including ports 27017 and 27018). Use read-only credentials for source access;
never insert, update, delete, migrate, seed, reset, change indexes/configuration,
or run attacks/load tests against a real source. Disable automatic index creation
and other startup writes when accessing a source. Copying is source-read-only:
all resulting writes must target a separate test database or local export.

Security tests must use an owned, isolated disposable MongoDB instance with
synthetic records or a sanitized copy. Remove/replace personal identifiers,
password hashes, tokens, session data and credentials before using copied data
in tests. Keep exports private, out of Git and logs. Never send copied data to
external providers without explicit user authorization.

Assert the effective test URI equals the URI generated by the fixture before
connecting, and ensure it differs from the source URI. Test processes must not
load real `.env` files or use source credentials. Source connection settings may
be used only for read-only inspection/export, never for a test target. Tests
must not call real email/AI/OAuth services unless separately authorized with
dedicated test accounts and synthetic inputs. Prevent notifications to real
users. Simulate outages by stopping only the instance the current test created.
Source-only static/secret scans are permitted; redact findings and never
validate discovered credentials against services.
